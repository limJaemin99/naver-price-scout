# 🛒 naver-price-scout — 네이버 쇼핑 최저가 일괄 조회 도구

품목 리스트 엑셀을 업로드하면, **네이버 쇼핑 검색 API**로 각 상품의 최저가를 일괄 조회하여
**확정 / 확인필요(사유 포함) / 검색결과없음**으로 자동 분류하고, 결과를 엑셀 2종으로 내려주는
**단일 HTML 웹앱 + Cloudflare Pages Functions 프록시** 프로젝트입니다.

> **절대 원칙:** 확실하지 않은 정보는 반드시 "확인필요"로 표시하고 사유를 기록합니다.
> 과잉 확신(잘못된 확정)이 미탐지보다 훨씬 나쁩니다 — 이 결과로 최종 보고서를 만들기 때문입니다.

빌드 도구·프레임워크 없이 **순수 HTML + CDN(ExcelJS)** 단일 파일(`public/index.html`)로 동작합니다.

---

## 아키텍처

```
[브라우저: public/index.html 단일 파일 앱]
  ├─ 엑셀 업로드/파싱 (ExcelJS, CDN)
  ├─ 검색어 생성 + 미리보기/수정
  ├─ 순차 API 호출 (fetch → /api/search)
  ├─ 판정 파이프라인 (확정/확인필요/검색결과없음)
  └─ 결과 엑셀 2종 생성/다운로드 (ExcelJS)

[프록시: /api/search]  ── 브라우저 → openapi.naver.com 중계 (CORS 우회)
  ├─ 배포:  functions/api/search.js   (Cloudflare Pages Function)
  └─ 로컬:  server.js                 (node, 내장 모듈만 사용)
```

- **API 키는 서버에 저장하지 않습니다.** 브라우저 `localStorage`에만 보관하고, 헤더
  `X-Naver-Client-Id` / `X-Naver-Client-Secret`으로 프록시에 전달하면 프록시는 그대로 릴레이만 합니다.
- 프록시 인터페이스(`GET /api/search?query=&display=&start=&sort=`)가 로컬·배포 양쪽에서 동일하므로,
  **같은 `index.html`이 두 환경에서 그대로 작동**합니다.

## 사용 방법 (6단계 위저드)

1. **키 설정** — Client ID/Secret 입력 → **연결 테스트**로 정상 작동 확인.
2. **파일 업로드** — 엑셀(.xlsx) 업로드. 시트·헤더·컬럼 자동 감지(교정 가능) → 브랜드 체크박스(기본 클리오).
3. **검색어 미리보기** — [품명 → 검색어] 표. 관리코드 괄호는 제거, 콜라보·에디션은 유지. 각 검색어 인라인 수정 가능(수정 내역은 브라우저에 저장되어 다음에 자동 적용).
4. **실행** — 고유 검색어를 순차 조회. 진행률·실시간 로그·일시정지/재개/중단. 결과는 브라우저(IndexedDB)에 캐시되어 **새로고침 후 이어하기**·**임계값 튜닝 시 API 재호출 없이 재판정** 가능.
5. **결과 확인** — 판정별 탭(전체/확정/확인필요/검색결과없음) + 사유·판매처·링크. `확인필요`는 링크로 직접 확인.
6. **다운로드** — 결과 엑셀 2종.

> ⚠️ `index.html`을 파일로 직접 열면(`file://`) 네이버 API가 CORS로 차단됩니다.
> 반드시 `server.js`(로컬) 또는 Cloudflare Pages(배포)로 접속하세요.

## 판정 규칙 (지시서 6장)

각 검색 결과 40건(정확도순)에 대해 순서대로:

1. **세트성 키워드 양방향 검사** — 결과에만 세트(세트·기획·증정·리필·미니 등)가 있거나, 원본이 세트인데 결과가 단품이면 후보 탈락. (원본의 ~45%가 세트/기획을 포함하므로 단순 제외가 아닌 **양방향** 비교)
2. **토큰 매칭** — 검색어 토큰 중 결과 제목에 포함된 비율. 0.8↑ 유지 / 0.5~0.8 부분일치 / 0.5미만 탈락. **옵션코드·색상은 필수 토큰**(경계 인식 매칭으로 `5⊄25`, `코랄⊄코랄베리` 오확정 차단).
3. **용량/수량 비교** — 원본과 결과의 용량(ml/g/정/개월…)이 불일치하면 탈락.
4. **가격 이상치** — 최저 후보가 생존 후보 중앙값의 절반 미만이거나 소비자가의 15% 미만이면 "가격 이상" 표시(미끼상품 방지).
5. **최종 판정** — 카탈로그(productType=1)·토큰 100% → **확정** / 마킹 있으면 **확인필요**(+사유) / 후보 0건 → **검색결과없음**(+최다 탈락 사유).

모든 임계값·키워드는 `public/index.html` 최상단 **`CONFIG` 블록**에서 관리합니다(아래 튜닝 참조).

## 결과 엑셀 2종

공통 추가 컬럼: `검색어(실사용) / 최저가 / 판매처 / 상품링크(하이퍼링크) / 판정 / 사유 / 감지용량 / 배송비(수동입력) / 조회일시`.
행 배경색으로 판정 구분(확정=연녹 / 확인필요=연노랑 / 검색결과없음=연회색). 배송비는 링크 확인 후 직접 입력하는 빈 칸.

- **① 결과_원본형.xlsx** — 업로드 원본의 모든 행(선택 브랜드, 재고 로트 중복 포함) 유지 + 공통 컬럼.
- **② 결과_보고서형.xlsx** — 품명 단위 병합(유통기한=가장 임박, 재고=합계, 공급가=최솟값) 후 카테고리별 정리(구분행 + 세부 단위 번호). `세부`=대표명, `제품명+색상`=브랜드 접두 제거.

## 로컬 실행

사전 준비물: [Node.js](https://nodejs.org) 18 이상. (외부 패키지 설치 불필요 — Node 내장 모듈만 사용)

```bash
node server.js      # 또는  npm start
```

실행 후 브라우저에서 **http://localhost:3000** 접속.

---

## 배포 (Cloudflare Pages)

1. Cloudflare 대시보드 → **Workers & Pages → Create → Pages → Connect to Git**
2. 이 저장소(`naver-price-scout`) 연결
3. 빌드 설정: **Framework preset** None · **Build command** *(비움)* · **Build output directory** `public`
4. 배포 후 `functions/api/search.js`가 자동으로 `/api/search`로 동작합니다.

---

## 네이버 검색 API 키 발급

1. [developers.naver.com](https://developers.naver.com) → **Application → 애플리케이션 등록**
2. 사용 API에서 **검색** 선택
3. 발급된 **Client ID / Client Secret**을 앱 "키 설정" 단계에 입력 (키는 브라우저 `localStorage`에만 저장)

- 무료, **일일 호출 한도 25,000건** (클리오 고유 품명 538개 기준 여유 충분)
- 아무 네이버 계정으로나 발급 가능 (스마트스토어 커머스API와는 완전히 별개 시스템)

## 튜닝 (`CONFIG` 블록)

`public/index.html` 상단 `CONFIG`에서 조정합니다. 주요 값:

| 항목 | 의미 |
|---|---|
| `DISPLAY` / `SORT` | 검색당 수신 건수(40) / 정렬(`sim` 정확도순) |
| `CALL_DELAY_MS` / `RETRY_BACKOFF_MS` | 호출 간 딜레이(150ms) / 429·네트워크 백오프(1s→2s→4s) |
| `STRIP_PAREN_*` | 검색어에서 제거할 관리코드 괄호(채널/시즌/버전 등) |
| `SET_KEYWORDS` | 세트성 키워드(양방향 검사) |
| `TOKEN_MATCH_FULL/PARTIAL` | 토큰 일치 임계값(0.8 / 0.5) |
| `PRICE_MEDIAN_FLOOR` / `PRICE_VS_RETAIL` | 가격 이상치 임계(중앙값×0.5 / 소비자가×0.15) |
| `CATEGORY_RULES` | 보고서형 카테고리 자동분류 키워드 |

**정답지 대조 검증**: `202706월이후` 시트의 사람이 정리한 `분류`를 정답지로 삼아 `categorize`를 대조한 결과, 지시서가 정의한 6개 카테고리 내 **약 95% 일치**(팩트 97%·아이 98%·아이브로우 100%·립 95%·치크 88%·하이라이터 76%). 정답지의 `소품`·`립.치크` 등 추가 분류는 지시서 규칙상 `기타`/`립`으로 처리됩니다.

## 프로젝트 구조

```
public/index.html          앱 전체 (단일 파일: CONFIG · 순수 로직 LOGIC-BLOCK · JUDGE · UI)
functions/api/search.js    Cloudflare Pages Function 프록시 (배포용)
server.js                  로컬 개발 서버 (Node 내장 모듈)
```

`index.html`의 `/* ===LOGIC-BLOCK-START/END=== */` 사이 순수 로직(파싱·검색어 생성·판정)은 브라우저/Node 공용으로, 외부 검증 하네스가 실제 소스를 추출해 테스트할 수 있게 유지합니다. 판정 로직은 **결과 5단계의 `🧪 판정 로직 자체 테스트` 버튼**으로 콘솔에서 검증할 수 있습니다.
